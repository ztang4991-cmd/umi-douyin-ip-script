# v0.1 技术选型与 Sprint 切分

## 技术选型

v0.1 使用 Python + SQLite + 原生前端做本地单体应用。

原因：

- 小白鼠试运行更看重能跑真实业务和可恢复数据，不需要先引入复杂部署链。
- SQLite 足够支撑 1-2 家门店早期试运行，并能用唯一索引强约束档期冲突。
- 原生前端减少依赖安装失败风险，便于快速迭代 CRM、档期、订单和看板。

后续若进入正式 SaaS 化，可迁移为 FastAPI/Django + PostgreSQL + React/Vue，当前数据模型可平滑迁移。

## Sprint 1

- 项目初始化
- 多租户、账号登录、角色权限
- 线索 CRM、第三方推荐字段、查重、跟进记录
- 销售助手嵌入线索详情

## Sprint 2

- 线索转商机
- 商机分配
- 档期资源与日历
- 正餐、试菜、临时锁台
- 档期冲突硬校验

## Sprint 3

- 商机转订单
- 合同 PDF 上传
- 收款记录
- 第三方渠道继承和返佣统计
- 老板经营看板与明细下钻
